# 0.14.1 interface-fidelity reconciliation

Milestone 0.14.1 restores the authenticated application delivered by the
0.14.0 platform cutover. It is an internal pre-release checkpoint, not a
release, tag, deployment, image or package publication, compatibility promise,
or production-library authorization.

The accepted references are protected only for the surfaces they were designed
to decide:

- [Variant M at `026e3388c`](https://github.com/atabbott/mechanical-librarian/tree/026e3388c86f583af5d5a136c4bf6a4192a77af6), retained on the remote

Ordinary implementation variance is permitted, but not a different
composition, hierarchy, typography, palette, theme treatment, responsive
model, or interaction language. A later reference cannot grant authority over
a surface it did not decide.

## Reconciled application

Library remains the complete current-work surface and keeps automatic-only,
clear, resolved, pre-admission, and retired work inspectable. Attention is the
first, field-level view of work that benefits from an owner decision. Both lead
with readable work, author, library, and destination language when current data
provides it, while retaining bounded search, lenses, pagination, stable direct
links, empty states, and local failure recovery.

Review detail keeps identity, current value, each eligible proposed value,
reviewer facts, notices, progressive evidence, and history distinct. The
current value and every specific eligible proposed value are the choices;
selecting one records only that field and advances predictably. There are no
generic Accept, Keep, or Reject controls and no separate submit step. Stale,
failed, rejected, or ambiguous mutations never report false success. When a
failed or ambiguous outcome cannot be followed by an authoritative detail
read, the interface does not claim that the case was refreshed: it blocks every
choice and retry for that case across persistent-workspace remounts. Only a
later successful authoritative detail read made after the lock clears it and
restores eligible choices.

Policy is the refined semantic field notebook with synchronized desktop and
compact chapter navigation, readable active and draft state, supported posture
and representation choices, impact, validation, and activation review.
Activity is the calm consent, readiness, guarded-work, history, pause, revoke,
and grouped-recovery ledger. It uses readable identity and scope-accurate
language without introducing a queue, retry system, monitoring burden, or new
write authority.

All five routes remain directly addressable inside one persistent authenticated
React shell. Primary data establishes a route while independent evidence and
history load progressively and fail locally. Desktop and 390-pixel layouts use
one editorial visual system in light and dark themes without horizontal page
overflow, clipped navigation, hidden decision outcomes, or unsafe rendering of
long or hostile content. Keyboard operation retains semantic names, visible
focus, skip behavior, focus restoration, and reduced-motion treatment.

## Authority and safety boundary

This reconciliation changes presentation and bounded display projections only.
FastAPI remains the sole authentication, CSRF, currentness, policy, mutation,
persistence, and recovery authority. The exact-current schema, report-only
defaults, explicit library consent, backup readiness, field-local plan
validation, supported-service API writes, read-back verification, ambiguity
recovery, durable audit, hostile-input bounds, read-only media, reviewer
isolation, and one-container deployment contract remain unchanged.

## Qualification contract

The final candidate is accepted only from one clean exact head. The hosted
public pull-request gate combines the fast source cohort, the required
exact-installed cohort, and the protected browser cohort. Pinned frontend
generation, types, lint, tests and deterministic build, architecture and
clean-schema checks remain within those owned jobs. The explicit exact-head
slow/resource cohort and exact-container lifecycle qualification run
separately; a green hosted public gate does not substitute for either result.
Generated OpenAPI, TypeScript DTOs, configuration schema, packaged assets,
licences, and documentation must agree with the same head.

Direct inspection of the installed application supplements automation. It
compares every governed surface with its own reference at desktop and 390
pixels in light and dark themes, and exercises keyboard/focus behavior plus
representative long, hostile, loading, empty, failure, stale, and ambiguous
states. Functional browser checks are necessary but do not substitute for this
visual comparison.

The checkpoint adds no metadata capability, decision outcome, batch authority,
schema or migration, production-library use, release, tag, deployment, image
publication, or frontend-platform replacement. A later first-release decision
remains a separate maintainer action with its own release gates.
