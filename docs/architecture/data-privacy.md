# Data privacy

## Contributor workbench

The repository-only workbench accepts synthetic fixtures, explicitly supplied
test workspaces, or an explicitly approved private corpus. Disposable state is
the default. It rejects production workspaces and targets and offers no force
bypass. Results expose only bounded status, artifact identifiers, byte counts,
and SHA-256 digests; operation exceptions are replaced with closed diagnostics.
Network experiments require a named isolated profile whose sanitization and
bounded authority bind the exact input-file digests and are recorded before
every attempt. Service configuration admits only loopback or `.invalid` origins
and workspace-confined private paths; fixed-origin production metadata providers
remain disabled unless a focused fake operation replaces the composition seam.
Persistent `.workbench/` state is ignored
by version control. Workbench code and state are absent from the wheel and
production container.

Cover packets retain only owner-private report-bound previews and canonical
packet/result artifacts. Model context receives opaque candidate references,
preview digests and dimensions, incumbent state, and bounded public provider
provenance; it receives no target, library/service identity, path, URL,
credential, raw provider response, provider work/edition identity, or private
bibliographic target value. Ephemeral image copies are mounted read-only and
removed with the reviewer job. Public qualification evidence is aggregate-only.

## Review preparation progress

The authenticated preparation surface exposes only configured connection and
library names, an opaque scan identifier, a closed state, checked/total/ready/
blocked counts, and whether another owner request was coalesced. It never
projects item titles, authors, filenames, media paths, provider queries or
responses, credentials, failure text, or report values. Normal review items
remain governed by the existing private/no-store Library and Attention
contracts. Persisted operational work rows use existing opaque target, file,
report, proposal, and case identities with exact source/producer identity and
fixed stage and failure codes. One bounded current work ledger per discovered
eligible item is reconciled in place; run history does not accumulate.


The current pre-release application minimizes retained data to one neutral
evidence document per distinct observation. It retains the configured logical
connection/library names,
target item identifier, current title, opaque file identity and digest, bounded
local field claims and results, fact-local opening excerpts of at most 280
characters, bounded source/DOM occurrence and rear-spine provenance, and
bounded provider candidate title/identifier fields and opaque provider-local
work identities. Open Library may add only its closed finite rich-evidence
allowlist: bounded upstream identities and provenance, selected identifiers and
classifications, subjects, edition characteristics, contributor identity and
role, edition-work relation, first-publication date, and cover IDs.
Google Books retains only bounded volume IDs, qualified claims, format and
edition signals, and an explicit unresolved work-link marker. Its
`publishedDate` value is typed evidence, never a selectable date claim.
The target projection retains exactly 16 bounded Audiobookshelf destinations,
fifteen of which are write-capable guarded destinations (narrators joined with
F47).
Provider cover rows retain only safe opaque source/work/edition identities,
typed designation, allowlisted edition context, artifact digests, dimensions,
media type, and preview references.
Provider discovery additionally retains opaque lane identities, exact local
claim references, normalized ISBN families, and provider-local edition/work
identities. It retains no request URL or raw lane payload. Same-provider lane
convergence remains one lineage and cannot count as independent corroboration.
One ProposalSet per distinct exact report/policy result retains only the report
ID, derived target fingerprint, fixed policy version, bounded candidate values,
assessments, evidence references, hashed correlation groups, reasons,
dependencies, and an optional selected alternative ID. It does not duplicate
report excerpts, provider evidence records, target current-state storage, or
cover provenance.

It does not retain credentials, Google Books API keys, authorization headers,
provider cover URLs, the Open Library
operational contact email, endpoint paths, private filesystem paths, raw
target/provider responses, arbitrary upstream properties or links, arbitrary
EPUB fragments, inventory, cover bytes, raw reviewer streams, reasoning,
malformed output, qualification profile paths, auth state, job files, request
bodies, logs, or support bundles. The contact email is also excluded from
report and manifest identities and every application fingerprint. Fixed stderr
diagnostics contain no rejected values.

The isolated child returns one bounded result for one EPUB session; neither its
input snapshot nor source body is retained after the report projection.

Reports and ProposalSets are append-only and provide no retention, pruning,
purge, export, or deletion feature. Operators must account for that deliberate limitation
when selecting the database location and backup policy.

Review cases are likewise append-only, retaining only the already bounded
ProposalSet projection and target facts needed for exact currentness. Admission
does not add reviewer identity, decision text, raw evidence, or service secrets.

Deterministic decision and outcome persistence retains the source-validated
packet projection and closed action/evidence identities required by the fixed
engine. It adds no model result, executable/profile identity, request, attempt,
dispatch process fact, raw stream, reasoning, or model advice. The source-only
contained reviewer persists no product data; its disposable workbench artifacts
remain private and outside installed runtime state.

Installed cover consideration is a narrow exception to that generic lifecycle.
It retains the exact bounded request and profile identities plus one locally
admitted closed visual observation or typed value-free failure needed for
immutable consideration history. It never retains raw model streams, prompts,
reasoning, private paths, credentials, process facts, or unadmitted output. The
observation contains opaque candidate references and the fixed visual vocabulary
only; deterministic identity/policy and the owner's explicit outcome remain
separate authoritative facts.

Policy Preview additionally retains append-only canonical deterministic outcome
sets. They contain only opaque case/report/proposal/target fingerprints,
policy/profile/generation and fixed rule/catalogue identities, closed
dispositions, action/candidate identities, and evidence/combination references
already admitted to the bounded case. They add no raw evidence, title, item,
path, credential, provider response, model output, human identity, or decision
text. Authenticated samples request at most 50 records and are truncated at one
MiB without adding a pagination or export surface. There is no per-outcome
purge, retention, or selective export command.

Rich-field draft impact is a transient authenticated projection, not another
persisted outcome. It can expose the current target value, exact admitted
desired value, full qualified series memberships, and stable abstention reason
for at most 20 current cases per library. The HTTP response remains
private/no-store. The equivalent CLI writes that private projection to stdout;
operators must not place it in public logs or support artifacts.

The public F20 rich-metadata qualification candidate contains only closed
option identities, aggregate dispositions and metrics, contract digests, and
zero-tolerance counts. It contains no corpus identity, case row, bibliographic
value, identifier, path, source digest, receipt, or per-case result; the
underlying retained material and offline replay result remain owner-private.
Prior unrelated use is an aggregate method fact, not a disclosure of which
work supplied any field-option result.
Subjective-field qualification compares only aggregate provenance and operation
outcomes; it does not publish or manufacture a preferred genre, tag set, or
description for any work.

The complete application SQLite database—including deterministic packets and
outcomes—is exposed to whoever can read a backup. Store it and its backups as private
application state with owner-scoped access and encrypted-at-rest backup
controls. The current application has no per-record purge, pruning, selective
export, or retention command; recovery and deletion operate on the complete
database.

Prior and intermediate development databases are never imported, migrated, or
rewritten. Operators may retain them offline, subject to the same data-handling
obligations, but recovery for the current increment uses a clean database and
supported report regeneration.

Field-effect plans, consent/authority facts, closed recovery actions, cleanup
obligations, and append-only events retain bounded pre-values, desired values,
closed identities, state, attempts, and failure codes for
attribution and recovery. Raw prior cover bytes are deliberately excluded.
They exist only in a bounded owner-mode private recovery directory, named by a
plan digest, and are removed through a persisted retryable obligation on every
verified, stale, superseded, or abandoned terminal path. Explicit absence is a
private sentinel distinct from arbitrary or missing recovery data.
Application documents, APIs, logs, diagnostics, fixtures, exports, support
bundles, and reviewers must never contain those bytes or their private path.

The supported Audiobookshelf canary may read one immutable original cover by
its plan-bound digest solely to stream one multipart upload. It does not retain,
log, export, or expose those bytes; pre-write cover bytes remain recovery-only.

The retained local vocabulary includes bounded title/subtitle, creator/contributor
roles, series/sequence, ISBN, dates, publisher/imprint, description, language,
and contextual subject evidence; it retains no paths or source bodies.
Edition and rights remain outside that public report vocabulary. Their private
qualification labels and exploratory aggregates are not retained in reports or
committed to the repository.

Operational timings retain only closed stage and wait-class codes, millisecond
duration and timestamp, capped at 256 records and disabled by default. Typed
status contains closed causes and narrow opaque scope identifiers, never field
values. Support preview/export is capped, allow-listed and re-redacted at export;
raw databases, environment, auth state, secrets, paths, metadata, excerpts,
media, covers and recovery bytes are categorically excluded.

## Authenticated Activity history

The private no-store Activity history returns only one bounded page
of existing ledger facts: opaque event/work identities, configured logical
library and destination names, state, bounded timestamp, a bounded readable
report title where it is already retained, and the exact before/after field
values the event's own decision, plan or verification document already holds,
rendered as bounded readable text. Those values are the owner's own library
metadata, already readable on Library and review; nothing is joined in to
produce them, and an opaque durable identity -- a cover token, a candidate
identity, a provider origin -- is described rather than printed. It is not an
export or a write surface, and grants no recovery or target authority. Search, range, page, and
page size are bounded; the parameterized query and closed response prevent
caller-supplied SQL or arbitrary stored JSON from becoming output. Corrupt or
hostile stored documents fail closed with a redacted diagnostic, never raw JSON,
paths, values, or a fabricated guard/verification assertion. The durable ledger
is append-only; count/page consistency applies only to its one read snapshot,
and retention remains the existing record-retention policy. Tests cover bounds,
stored-row corruption, source-specific evidence, current-state recovery, and
authenticated private-cache behavior.

The process may also retain up to 64 MiB of serialized readable Activity facts,
search text and source/dependency witnesses. This private in-memory store is not
an export or another durable ledger. It retains no domain report objects between
requests and disappears with its runtime owner; canonical retention is unchanged.

## Compact retained cover evidence (#1158)

Cover considerations retain their full immutable packet and reference the exact
canonical report already retained in the application database. Expanded public
and application documents are unchanged. This removes duplicate representation,
not evidence: reports, histories, originals and previews retain their existing
privacy, backup and retention obligations. No pruning or new cleanup is enabled.
