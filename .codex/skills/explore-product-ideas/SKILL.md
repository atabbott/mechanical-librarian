# Explore a product idea

Use Tier 0 from `.codex/operating-policy.md`. This workflow is read-only unless
the user explicitly approves a dossier or tracking mutation.

## Understand the idea

Clarify the user problem, desired outcome, affected users, constraints, and what
would count as evidence. Challenge assumptions without turning uncertainty into
a design requirement.

Use bounded `reader` tasks for independent market, technical, repository, or
workflow questions when parallel research will materially help. Prefer primary
sources and distinguish facts, inference, and open questions.

## Develop options

Compare the smallest useful outcome with credible alternatives. Cover product
value, operational cost, privacy and safety, dependency or compatibility risk,
and fit with the existing roadmap. Avoid implementation planning before the
idea is mature enough.

## Preserve and place

With user approval, record a private dossier under `.codex/ideas/` using
`references/idea-dossier.md`. Keep credentials, personal paths, production data,
and unredacted reports out of it.

Recommend one disposition: continue exploration, roadmap candidate, functional
slice, focused change, deferred idea, or reject. Create or mutate tracking only
with explicit user authority. Do not implement the idea in this workflow.
